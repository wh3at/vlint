# terminalで設定URLと実測URLを生値で示す

対象ページの設定URLと実測URLは成功・失敗を問わず対象ページとデバイスごとにterminalとJSONの両方へ生値で出力し、terminal側のquery値・hashの伏せ字を廃止する。ブラウザーで実測できなかった場合は実測URLを空として扱い、途中の遷移が検出されて失敗した場合はその失敗にも検出URLを示す。実測URLが異なる理由をそのまま確認でき、形式間の挙動も揃う一方、URLに秘密情報を含めた場合はterminalログに残る。URLに秘密情報を含めない運用を選び、ログを扱う側がその責任を負う。制御文字の安全な表示処理は維持する。

## 通常出力と完全レポートへの分離

[検査環境の設定と受け入れ基準をどう統合するか](https://github.com/wh3at/vlint/issues/48#issuecomment-6206182064)で、成功時も全ケースを通常出力へ列挙する方針を置き換えた。通常出力は環境・ルールごとの検査範囲サマリーと違反・失敗への対処に必要な情報に絞り、全ケースを含む完全な結果は実行ごとにOSの一時領域へJSONで保存して、そのパスを返す仕様とする。

通常表示するケースと完全レポートでは、指定URL・実測URLのquery・hashを含む生値表示と制御文字の安全処理を維持する。URLの厳格な照合は変更しない。

[#55](https://github.com/wh3at/vlint/issues/55)で製品コードへ反映した。terminalとJSONの通常出力に返す`reportPath`から、同じ実行の完全レポートを取得できる。保存とCIでの保持方法は[完全レポート](../operations/reports.md)を参照。
