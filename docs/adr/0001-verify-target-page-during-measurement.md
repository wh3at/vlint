# 計測境界で対象ページとready状態を検証する

`vlint check` がredirect後の別ページを検査してもcleanになり得る現状に対し、対象ページのURLを標準的に正規化したうえでorigin・path・query・hashを照合し、異なる到達先は対象ページごとに列挙された許可URLだけを認める。取得後に許可された到達URLを固定し、別の許可URLへの移動も失敗とする。各ルールのDOM取得時にはURLとready状態を検証し、非同期評価中に検出した遷移やready解除も失敗とする一方、ルール間は次の計測開始時に再確認する。CSSだけによる検出不能な瞬間的変化は保証外であり、アプリ側の新たな通知機構は設けない。厳格な照合は既存のredirect利用に影響するが、暗黙に到達先を信用して偽のcleanを返すよりも、例外を明示させることを選んだ。アプリ固有のready条件を設定していない対象ページには、従来の読込・フォント完了を超えるready保証を付けない。
